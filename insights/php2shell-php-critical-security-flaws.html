PHP2Shell: two critical flaws expose the risk of unpatched websites

PHP released fixes for two serious vulnerabilities on 21 October. They are a reminder that website security is an ongoing responsibility.

Event date: 21 October 2026

9.2
Written and published 10 November 2026. The date above refers to the event or measurement period, not the original publication of this article.

What happened

On 21 October 2026, the PHP project published fixes for CVE-2026-109618 and CVE-2026-109619, known collectively as PHP2Shell. The two memory-management problems could allow attackers to execute code remotely in vulnerable PHP environments without first signing in.

Both were rated 9.2 under CVSS version 4 by the PHP security team. The vulnerabilities affected PHP installations serving web requests, making the story relevant to the wider hosting and content-management ecosystem.

What owners of PHP websites should know

PHP underpins a substantial range of web applications, but a particular website's exposure depends on its server configuration, PHP version and whether fixed packages have been installed. This was a runtime problem, so updating a WordPress theme alone would not address it.

The PHP project released corrected versions 8.2.35, 8.3.36, 8.4.27 and 8.5.12. Older PHP branches such as 8.1 are end-of-life, making migration to a supported version particularly important.

The lesson for businesses

The most valuable maintenance is often invisible. A website may look exactly the same before and after a vital security update, yet be in a very different position technically.

Ask whoever hosts or maintains your site how server updates are handled, who checks security advisories and what happens when urgent patches are released. Security is a process, not a one-off feature bought at launch.

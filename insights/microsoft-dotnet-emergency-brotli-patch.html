SecurityEvent date: 25 October 2026

Microsoft issues an emergency .NET security update

A Brotli decoder vulnerability prompted an out-of-band patch for .NET 8, 9 and 10. The wider lesson is that third-party components need attention too.

OOB

Security / 2026

Written and published 10 November 2026. The date above refers to the event or measurement period, not the original publication of this article.

What happened

On 25 October 2026, Microsoft released security updates outside its normal schedule for .NET 8, .NET 9 and .NET 10, alongside .NET 11 Release Candidate 3. The immediate issue was CVE-2026-111497, a serious vulnerability in the Brotli decompression code used by software across the web ecosystem.

Microsoft described a buffer overflow that could allow an unauthenticated attacker to read or corrupt process memory. Depending on the exposure, the consequences could include information disclosure, service interruption or privilege escalation. The update also addressed a separate Linux tarball ownership issue.

Why this matters for websites

A website can be carefully designed and still depend on software that develops vulnerabilities after launch. Brotli is a compression technology, not a visible page feature, which makes this a good example of security work that most customers will never notice.

Importantly, not every .NET website was automatically exploitable. Microsoft's advisory identifies particular decompression APIs and configurations as relevant, and notes that some automatic decompression options are disabled by default.

The practical takeaway

Teams running affected versions should check their deployment setup and apply the appropriate patched runtime, SDK or container image. Self-contained applications need to be rebuilt and redeployed; upgrading the host alone may not replace bundled vulnerable code.

For a business owner, the lesson is straightforward: ongoing website maintenance is about keeping the foundations current, not just changing images or fixing visible problems.
